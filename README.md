# Student PDF Generator

Flask application that creates one downloadable PDF containing a personalized front page followed by the fixed report PDF.

## Requirements

- Python 3.10 or newer
- Microsoft Word on Windows for `docx2pdf`, or LibreOffice for headless conversion
- The fixed assets in `templates/`:
	- `frontpage.docx`
	- `report.pdf`

## Installation

Create and activate a virtual environment, then install dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Restore `templates/frontpage.docx` and `templates/report.pdf` if they are not already present. Then run the administrator setup script once:

```powershell
python setup.py
```

`setup.py` creates `templates/frontpage_template.pdf` using `docx2pdf` first and LibreOffice as a fallback. The normal `/generate` request never converts DOCX files.

Start the application:

```powershell
python app.py
```

Open `http://127.0.0.1:5000/` in a browser. For production, run the Flask app behind a production WSGI server and HTTPS, and set a strong `STUDENT_PDF_SECRET_KEY` environment variable.

## Configuration

Edit `config.py` to adjust the overlay coordinates. Coordinates are ReportLab points measured from the bottom-left corner of the first-page PDF. Each field supports `x`, `y`, `font_size`, `font_name`, `mask_width`, and `mask_height`.

The application removes generated PDFs older than one hour before each new generation. Technical failures are logged in `logs/error.log`, while users receive a generic error message.

## Security

- Users can submit only Student Name and Register Number; there is no upload endpoint.
- CSRF tokens are stored in the Flask session and checked on every POST.
- Names and register numbers are length-limited and sanitized before becoming filenames.
- `/download/<filename>` rejects path traversal and only serves `.pdf` files from `output/`.
- Do not expose `output/` or `logs/` as static directories in a reverse proxy. Keep the project behind HTTPS in production.

## Asset note

The binary DOCX and PDF assets are not generated by source code. They must be supplied by the administrator. Without `frontpage.docx` and `report.pdf`, setup and generation intentionally fail with a clear error instead of creating invalid output.
# Student PDF Generator

Small PHP application that creates one downloadable PDF containing a personalized front page followed by the fixed report PDF.

## Requirements

- PHP 8.1 or newer with `mbstring`, `iconv`, and `fileinfo` enabled
- Composer
- LibreOffice installed; setup searches the Windows standard install locations and `PATH`
- Apache with `mod_rewrite`/directory access rules enabled, or equivalent web-server protections

## Installation

1. Place the project outside the public web root where possible, exposing only the application entry points.
2. Confirm the fixed assets exist:
	- `templates/frontpage.docx`
	- `templates/report.pdf`
3. Install dependencies:

	```text
	composer install --no-dev --optimize-autoloader
	```

4. Run the one-time setup command from the project root:

	```text
	php setup.php
	```

	This invokes LibreOffice once and creates `templates/frontpage_template.pdf`. The normal user request never invokes LibreOffice. On Windows, setup checks `PATH`, `C:\Program Files\LibreOffice`, `C:\Program Files (x86)\LibreOffice`, and the per-user install directory.

5. Edit the `overlay` coordinates in `config.php` if the DOCX cover has different positions for the name and register number.
6. Ensure the web process can write to `output/` and `logs/`.
7. Point the web server at the project and open `index.php`.

## Operation

Users submit only Student Name and Register Number. The server validates both values, checks the CSRF token, overlays the values on the cached front page PDF, appends every page from `templates/report.pdf`, and downloads a filename in the form `NAME_REGISTER_NUMBER.pdf`.

Generated PDFs older than 24 hours are removed when a new PDF is generated. Technical failures are logged to `logs/error.log`; end users receive a generic error message.

## Security notes

- Do not expose `templates/`, `output/`, or `logs/` directly. The included `.htaccess` files deny access on Apache.
- `setup.php` is CLI-only and should not be web-accessible.
- Keep Composer's `vendor/` directory available to the PHP application, but do not expose configuration or logs.
- For Nginx or another server, reproduce the same deny rules in the server configuration.

If LibreOffice is installed elsewhere, set `libreoffice_executable` in `config.php` to the full path of `soffice.com` or `soffice.exe` and rerun the command.

## Updating a source DOCX

Delete `templates/frontpage_template.pdf`, update `templates/frontpage.docx`, then rerun `php setup.php`. This is an administrative operation and does not happen during user generation.
